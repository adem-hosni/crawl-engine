# Agent State

**File:** `src/core/state.py`

Defines the `AgentState` TypedDict that flows through every node in the LangGraph.

---

## `AgentState`

```python
class AgentState(TypedDict):
    messages: Annotated[list, add_messages]
    user_goal: str
    summary: str
    current_url: str
    clean_dom: str
    interactive_elements: Dict[int, Any]
    todo_list: List[str]
    previous_actions: List[str]
    scratchpad: List[str]
```

| Field | Type | Description |
|---|---|---|
| `messages` | `Annotated[list, add_messages]` | Conversation history. Uses LangGraph's `add_messages` reducer, which appends new messages and keeps the list growing. |
| `user_goal` | `str` | The original task the user wants the agent to complete (e.g., "Create an account on discord"). |
| `summary` | `str` | Compressed summary of older messages (generated by the summarization node). |
| `current_url` | `str` | The URL the browser is currently on (updated by the perception node). |
| `clean_dom` | `str` | Parsed, simplified HTML showing only interactive elements with numeric IDs. |
| `interactive_elements` | `Dict[int, Any]` | Maps numeric element IDs to XPath selectors. Populated by `DOMCleaner`, consumed by `BrowserContext`. |
| `todo_list` | `List[str]` | A list of remaining steps the agent plans to execute. |
| `previous_actions` | `List[str]` | Log of recently executed actions (kept to the last 10). |
| `scratchpad` | `List[str]` | Working memory for the agent's intermediate reasoning. |

---

## How `add_messages` Works

LangGraph's `add_messages` reducer automatically:

1. **Appends** new messages to the existing list.
2. **Removes** messages when a `RemoveMessage` is returned (used by the summarization node).
3. **Updates** messages with the same ID (for tool call responses).

This means the `messages` field grows unboundedly unless explicitly pruned — which is exactly what the `summarization_node` does.

---

## State Lifecycle in the Graph

```
PERCEPTION  →  writes clean_dom, current_url, interactive_elements
STRATEGIST  →  reads all fields, writes new messages + previous_actions
EXECUTOR    →  reads interactive_elements (via BrowserContext), writes tool results to messages
SUMMARIZER  →  reads messages, writes summary + RemoveMessage for old messages
```

Each node only modifies the fields it owns, preserving the rest.
